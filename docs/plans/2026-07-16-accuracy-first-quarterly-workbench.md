# 准确性优先的季度估值工作台设计原则

## 产品定位

这个系统不应该按“每日交易信号工具”设计，而应该按“季度投资研究工作台”设计。

价值投资的关键不是频率，而是：
- 数据可靠
- 行业分类准确
- 估值方法匹配商业模式
- 关键假设可追溯
- 低估结论能被反方挑战
- 最终由人决定是否深入研究

## LLM 的最佳位置

LLM 不应该直接决定目标价，也不应该替代财务公式。

最佳实践是：

| 环节 | 是否用 LLM | 原因 |
|---|---|---|
| 数值计算 | 否 | 必须由代码和可追溯公式完成 |
| 行业/商业模式识别 | 可用 | LLM 可辅助识别公司真实业务，但要有数据源校验 |
| 估值方法选择 | 可用 | LLM 可解释为什么适合 DCF/PB/EV/EBITDA/股息模型等 |
| 关键假设生成 | 可用 | 用于提出增长率、利润率、资本开支等假设范围，但必须落入行业约束 |
| 风险识别 | 应用 | 很适合找财报外风险、周期位置、政策风险 |
| 最终结论 | 辅助 | 结论应来自模型结果 + 数据质量 + 人工确认 |

## 每个标的的估值方法选择

不要用单一 DCF 横扫所有公司。

推荐方法矩阵：

| 公司类型 | 主估值方法 | 辅助方法 |
|---|---|---|
| 稳定消费/品牌护城河 | DCF、Owner Earnings | PE、股息、同业估值 |
| 银行 | PB、ROE/COE 框架 | 股息率、不良/拨备压力测试 |
| 保险 | P/EV、PB | 投资收益率、偿付能力 |
| 周期资源/油服/有色 | 中周期 EV/EBITDA、PB | DCF 情景、商品周期位置 |
| 地产 | NAV、PB 折价 | 现金流压力、债务期限 |
| 公用事业 | DCF、股息折现 | EV/EBITDA |
| 高成长科技/软件 | DCF 情景、PS/EV Sales | PEG、单位经济模型 |
| 医药创新药 | 管线 rNPV | PS、研发阶段风险 |
| 困境/亏损公司 | 清算价值、重组价值 | 排除或观察 |

## 准确性门槛

批量扫描结果需要分级，而不是简单“低估/不低估”：

1. **可投资候选**
   - 数据质量高
   - 估值方法与行业匹配
   - 至少 2 个估值方法支持低估
   - 安全边际足够
   - 没有致命风险标签

2. **待深挖**
   - 低估明显，但数据不完整或方法分歧较大
   - 需要生成完整报告

3. **观察**
   - 估值接近合理区间
   - 或安全边际不足

4. **排除**
   - 数据质量过低
   - 长期停牌/ST/退市风险
   - 流动性不足
   - 财报异常无法解释
   - 周期利润峰值导致假低估

## 用户体验原则

本地控制台应服务一个季度工作流：

```
打开控制台
→ 检查 API 和数据源状态
→ 更新数据
→ 运行全市场/自选池扫描
→ 查看机会表
→ 对候选公司逐个生成深度报告
→ 记录人工结论
```

页面应该默认隐藏复杂性，但允许展开所有假设：
- 默认看候选表
- 点击公司看估值拆解
- 点击方法看公式和输入数据来源
- 点击风险看反方观点
- 点击“生成深度报告”才跑完整 LLM Agent

## 一键启动要求

项目根目录应保留一个可双击入口：

```
Start AI Value Investor.command
```

它启动本地控制台并打开浏览器。控制台首页至少显示：
- API Key 配置状态
- 数据源开关
- 数据库大小和表状态
- 历史报告
- 后续批量扫描入口

## 后续实现优先级

1. 本地控制台只读 MVP：配置状态、数据库状态、报告历史。
2. 批量估值轻量引擎：不生成报告，输出估值快照。
3. 可恢复扫描任务：支持季度全市场扫描。
4. 机会表：筛选、排序、导出。
5. 单公司估值详情页：公式、输入、方法权重、风险标签。
6. 从机会表一键生成完整报告。
7. 设置页：安全编辑 `.env`，带备份和连通性测试。

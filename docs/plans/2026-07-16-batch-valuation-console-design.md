# 批量估值扫描与本地控制台产品设计

## 目标定位

当前系统强项是“单家公司深度研报”。新增能力应定位为研报之前的漏斗：

```
全市场股票池 → 数据拉取/更新 → 快速质量门控 → 批量内在价值估算
→ 低估候选表 → 人工挑选 → 深度 Agent 流程 → 完整研报
```

核心产物不是长报告，而是一张可排序、可筛选、可解释的估值机会表。

## SQLite 数据清理最佳实践

不建议“每次启动删除一个月前所有数据”。

原因：
- SQLite 是磁盘文件，不常驻占用内存；当前 `data/` 约 15MB，实际压力很小。
- 财报历史、价格历史、历史 Agent 信号是估值、趋势判断、Graham 标准和回测的输入资产。
- A 股/港股批量扫描会更依赖缓存，启动即清理会导致重复请求、变慢、触发限流。

推荐保留策略：

| 数据类型 | 建议策略 |
|---|---|
| 财报、资产负债表、现金流 | 永久保留或至少 10 年 |
| 财务指标 | 至少保留 10 年 |
| 日线价格 | 默认 5-10 年；全市场模式可只保留日线近 3 年 + 月线长期历史 |
| agent_signals | 保留 90-180 天，或按 ticker/agent 只保留最近 N 条 |
| scan_logs | 保留 180 天 |
| macro/cache | TTL 自动刷新，可清理 7-30 天前缓存 |
| output/reports | 不自动删除，改为前端提供手动归档 |

最佳做法：
- 不在每次启动做重型清理。
- 启动时只做轻量 maintenance：建表、迁移、WAL checkpoint、过期 cache 清理。
- 提供“数据库维护”页面：查看体积、表行数、最早/最新日期、一键清理运行日志、一键 VACUUM。
- 清理任务可配置：手动、每周、每月，而不是每次启动。

## 批量估值业务逻辑

### 1. 股票池管理

股票池需要分层：
- 全 A 股
- 全港股
- 自选 watchlist
- 行业/主题池
- 排除池：ST、退市风险、长期停牌、成交额过低、财报缺失严重

前端应允许保存筛选条件为“扫描方案”，例如：
- A 股主板 + 中证行业 + 非 ST + 近 20 日成交额大于 5000 万
- 港股通 + 市值大于 50 亿港币
- 自选能源/银行/消费组合

### 2. 数据更新策略

批量扫描不应该对每只股票都跑完整 Agent。

建议分三层：

| 层级 | 用途 | 数据 |
|---|---|---|
| L0 快速行情层 | 判断当前价格、市值、流动性 | 最新价、成交量、市值、PE/PB |
| L1 快速估值层 | 批量计算内在价值 | 最近 3-5 年财报、财务指标、行业参数 |
| L2 深度研究层 | 对候选公司生成完整研报 | 全 Agent + LLM + 新闻 + 宏观 + Contrarian |

更新规则：
- 行情：交易日每日更新。
- 财报：按公告季更新；如果最新财报未变，不重复抓。
- 新闻/LLM：只在 L2 深度研究阶段启用，默认不用于批量扫描。

### 3. 批量估值方法

批量扫描需要“足够快、足够保守、可解释”，不追求单家公司研报那样完整。

建议每家公司输出：
- 当前价格
- 内在价值区间：bear/base/bull
- base 目标价
- 安全边际：`(base_intrinsic_value - current_price) / base_intrinsic_value`
- 估值方法组合：DCF、PB、PE、EV/EBITDA、股息折现、金融股 PB、困境/房地产专用模型
- 数据质量分
- 行业分类置信度
- 低估原因摘要
- 风险标签
- 推荐下一步：忽略 / 观察 / 生成深度报告

### 4. 判断逻辑

推荐设置三级结论：

| 结论 | 条件示例 |
|---|---|
| 强候选 | 安全边际 ≥ 30%，数据质量 ≥ 70%，至少 2 个估值方法支持 |
| 观察 | 安全边际 10%-30%，或方法分歧较大 |
| 排除 | 数据质量低、财报异常、流动性差、估值方法不可用、退市/ST/停牌风险 |

需要额外做“假低估”过滤：
- 周期行业在利润峰值阶段的低 PE。
- 金融/地产资产质量不透明导致的低 PB。
- 净利润为正但经营现金流长期为负。
- 一次性收益导致估值虚低。
- 成交额太低，真实可交易性不足。
- 港股仙股、老千股、长期折价控股公司。

### 5. 结果表格字段

默认表格字段：

| 字段 | 说明 |
|---|---|
| ticker/name/market | 股票代码、名称、市场 |
| industry | 行业 |
| price | 当前价 |
| intrinsic_base | base 内在价值 |
| intrinsic_range | bear-base-bull |
| margin_of_safety | 安全边际 |
| valuation_methods | 使用的方法数 |
| quality_score | 数据质量 |
| confidence | 估值置信度 |
| liquidity | 流动性 |
| flags | 风险标签 |
| action | 生成报告 / 加入观察 / 排除 |

高级筛选：
- 安全边际阈值
- 行业
- 市值范围
- ROE/ROIC
- 负债率
- 现金流质量
- 股息率
- 数据质量
- 估值方法数量
- 是否允许周期股/金融股/地产股/亏损股

## 本地前端设计

建议做成“本地控制台”，不是营销式首页。

### 导航结构

1. **扫描仪**
   - 选择股票池：A 股、港股、watchlist、行业池
   - 选择扫描方案
   - 设置阈值和排除规则
   - 启动/暂停/恢复扫描
   - 查看进度、失败原因、预计耗时

2. **机会表**
   - 默认按安全边际和质量分排序
   - 支持列配置、筛选、导出 CSV/XLSX
   - 每行可展开显示估值方法明细
   - 一键生成完整报告

3. **公司详情**
   - 批量估值 mini view
   - 财报快照
   - 估值瀑布图
   - 数据质量与风险标签
   - 历史扫描记录

4. **报告中心**
   - 已生成报告列表
   - 状态：生成中/成功/失败
   - 打开 Markdown
   - Telegram 推送状态

5. **数据源与 API**
   - OpenAI/DeepSeek/Anthropic
   - Tushare fast/super/official 模式
   - AKShare、QVeris、FMP、Tavily
   - 健康检查、额度、最近错误
   - 代理开关

6. **数据库维护**
   - 数据库大小、表行数、日期范围
   - 清理运行日志
   - 清理缓存
   - VACUUM
   - 导出/备份

### 关键开关

批量扫描开关：
- 使用 A 股 / 港股
- 允许调用 LLM：默认关闭
- 自动补财报：默认开启
- 跳过低流动性公司：默认开启
- 跳过 ST/停牌/退市风险：默认开启
- 使用 Tushare fast：默认开启
- 深度补数使用 Tushare super：默认开启
- 失败自动 fallback 到 AKShare/BaoStock/yfinance/FMP

报告开关：
- 对候选公司自动生成报告：默认关闭
- 只对强候选生成报告：可选
- 生成后 Telegram 推送：可选

## 后端实现建议

新增模块：

```
src/screening/universe.py          # 股票池获取：全A、全港股、watchlist
src/screening/batch_valuation.py   # 批量估值主流程
src/screening/filters.py           # ST、停牌、流动性、数据质量过滤
src/screening/jobs.py              # 扫描任务、暂停/恢复、进度
src/web/                          # 本地 FastAPI/前端接口
```

新增表：

```
valuation_scans
valuation_scan_results
data_source_health
app_settings
```

批量估值应复用现有 `valuation.py` 的方法，但要抽出一个“轻量评估入口”，避免每只股票都跑完整 Agent、LLM 和报告生成。

建议新增：

```python
run_batch_valuation(ticker, market, *, use_llm=False) -> ValuationSnapshot
```

它只做：
- 数据质量检查
- 行业分类
- 快速估值
- 安全边际判断
- 风险标签
- 结果入库

不做：
- Buffett LLM
- Graham LLM
- Sentiment LLM
- Contrarian LLM
- Markdown report

## 推荐迭代顺序

1. 抽出轻量估值函数，先支持 watchlist 批量输出 CSV。
2. 加全 A 股/港股 universe 获取与分页扫描。
3. 增加 scan result SQLite 表，实现可恢复任务。
4. 做本地前端的扫描仪和机会表。
5. 增加 API 设置页和数据源健康检查。
6. 从机会表一键触发完整研报。
7. 做数据库维护页和保留策略。
